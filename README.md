# KIRO: кампании (`kiro-campaigns`)

Визуальный редактор Telegram-кампаний для Remnawave Minishop (plugin API v1, Minishop 3.8.0+).

## Что умеет
- **Редактор в стиле n8n.** Кампания — граф блоков: триггеры, условия, действия, ожидания. Блоки перетаскиваются, связи тянутся от порта к блоку, есть отмена/повтор, проверка схемы и подсветка пути для выбранного пользователя.
- **Триггеры:** за N дней до окончания, N дней после окончания, после регистрации, после оплаты, нет подключений, рассылка по сегменту (сразу, в указанное время, ежедневно, по дням недели).
- **Условия:** оплатил, подписка активна, проверка аудитории (13 условий), случайное деление с контрольной группой.
- **Действия:** сообщение (HTML, RU/EN, картинка, до 4 кнопок, подстановки ядра), личный промокод (скидка, бонусные дни, трафик, Premium), уведомление админа.
- **Лимиты и безопасность:** лимит сообщений на человека в сутки, интервал между сообщениями, тихие часы с поясом, скорость отправки, кулдаун повторного входа, учёт согласия «маркетинг», учёт блокировки бота, главный выключатель движка, тест себе, сухой прогон.
- **Конверсия:** по кампании и по каждому блоку; сравнение с контрольной группой (прирост); точная привязка по промокодам и привязка по окну после последнего сообщения.
- **Аналитика:** выручка по дням (по валютам), платящие (новые/повторные), пробный → оплата, не продлили, тарифы, доля выручки после рассылок, CSV.

## Как это работает
Периодическая задача `tick` (раз в минуту) находит новых участников по триггеру, ведёт каждого по графу (`wait_until`, текущий блок) и пишет события в `ext_kiro_campaigns_events`. Отправка — через бота Minishop; подстановки, кнопки и проверка HTML — штатные функции ядра. Опубликованные версии схем неизменяемы: уже идущие участники дочитывают свою версию.

Таблицы: `ext_kiro_campaigns`, `_versions`, `_enrollments`, `_events`, `_settings`, `_images`.

## Структура
```
backend/kiro_campaigns/   storage, graph, audience, engine, reports, presets, core (адаптер ядра), __init__ (маршруты)
frontend/admin/index.js   собирается из tools/frontend_parts/*.js командой `python tools/assemble.py`
tests/run_engine_tests.py тесты движка и отчётов на временном PostgreSQL (pip install pgserver sqlalchemy[asyncio] asyncpg)
preview/index.html        страница с имитацией API для проверки интерфейса (python -m http.server)
```

## Проверка
```
python tools/assemble.py
python tests/run_engine_tests.py     # 65 проверок
```
Сборка и подпись пакета — `build.py` в родительской папке.

## Первый запуск
1. Установить плагин, открыть раздел «Кампании».
2. Вкладка «Настройки»: проверить пояс, тихие часы, лимиты. Движок по умолчанию **выключен**.
3. Создать кампанию из готового сценария (создаётся черновиком), проверить схему, «Тест мне», «Опубликовать».
4. «Запустить» (покажет, сколько человек подходит), затем включить движок в настройках.
